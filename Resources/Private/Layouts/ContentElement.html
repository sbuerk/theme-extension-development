The frame every content element renders through - the core set on "lib.contentElement", the theme's own on "lib.themeContentElement", both with this layout. The appearance fields of the record become modifiers of ".theme-content-element" (components/_content-element.scss): frame_class surface, raised, accent, inverse --frame-{value} none --frame-none space_before_class extra-small ... extra-large --space-before-{value} space_after_class extra-small ... extra-large --space-after-{value} Each field is matched against the values the theme styles, one "f:case" per value, and anything else renders no modifier at all: the default ("default", an empty spacing), a value the page TSconfig removed from the select ("ruler-before", "indent", ...) that an older record still carries, and a value nothing ever offered. A modifier that is written whatever the field holds is a class no rule matches - the defect the component contract exists to rule out, and "ContentElementContractTest" holds this file to it. "header_position" and "tx_theme_header_style" belong to the heading and are read by "Partials/ContentElement/Header.html", not here.
