"theme_pricing" - pricing plans side by side, on ".theme-pricing" (Resources/Private/Scss/components/_pricing.scss). The plans are "tx_theme_list_items", resolved the way "ThemeLinklist.html" resolves its rows - "tt_content.theme_pricing" is a reference to "tt_content.theme_linklist", the query without the nested "FilesProcessor", because a plan has no image. So "item.data.<column>" is the raw row of the child table and there is no "item.files". The columns of a plan, relabelled for this relation in "Configuration/TCA/Overrides/tt_content_theme_pricing.php": "header" is the name, "subheader" the price, "meta" what the price is per, "text" the features and "highlighted" the plan a site recommends. The link is the "theme_link_style" palette of the child, rendered as a button through "Partials/ContentElement/LinkButton.html" like a card of the card group. The plans are the items of a "ul", and their names sit one level below the heading of the element ("Partials/ContentElement/ItemHeading.html"). --- The features are one per line, and "f:split" needs a real newline ----- "text" is the plain text column of the child table, and a feature is a line of it - the convention the bullet list already uses for its own "bodytext", where the core "SplitProcessor" does the splitting. There is no processor for a column of a child row, so the template splits, with "f:split". The view helper belongs to Fluid rather than to TYPO3 and arrived in Fluid Standalone 2.11, so what decides whether it exists is the Fluid version, not the core one: "typo3/cms-fluid" requires "typo3fluid/fluid ^2.15.0" from 12.4.22 - the floor of this extension's own constraint - and "^4.0.1" and up on 13.4, so it is present on every version this branch supports. The separator below is a **literal line break inside the attribute value**, and it has to be: Fluid does not decode XML character references in an attribute, so "separator="&#10;"" splits on the five characters of the reference and returns the whole value as one unsplit feature - a plan whose features render as a single run-on line. Verified by rendering all three spellings through standalone Fluid before this was written; the tag content form ("<f:split></f:split>") throws, because "separator" is required. Do not "tidy" the line break away. An empty line is skipped rather than rendered as an empty item, so a trailing newline an editor left behind costs nothing. A feature a plan does **not** include is left out of its list. The alternative - a crossed out line, "xmark" - needs a per line syntax saying which is which ("- Audit log"), and inventing a micro format no editor is told about is the same mistake the definition list refused to make (see "docs/architecture/content-elements.md", the bullets section). A plan lists what it includes; the plan beside it is the comparison.
