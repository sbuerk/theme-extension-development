"theme_media_teaser_grid" - several media teasers in a grid, rendered through the existing ".theme-card-grid" of ".theme-card" items (see "docs/development/component-library.md#content") rather than a component of its own - it was built for exactly this shape. "header"/"bodytext" are the optional lead-in above the grid, rendered the same way every other element renders them (the shared "ContentElement/Header" plus a plain "f:format.html" body, see "Text.html"). The grid items themselves are "tx_theme_list_items", narrowed by "overrideChildTca" in "Configuration/TCA/Overrides/tt_content_theme_media_teaser_grid.php" to "header"/"text"/"image"/the "theme_link" palette - resolved by "TYPO3\CMS\Frontend\DataProcessing\DatabaseQueryProcessor" with a nested "FilesProcessor" for each row's own "image" (see "Configuration/TypoScript/ContentElements.typoscript"). Each entry in "listItems" is "['data' => $row]" plus whatever a nested "dataProcessing" added as a sibling key - "DatabaseQueryProcessor" wraps every record that way (see the identical note in "MenuCategorizedContent.html"), so the child table's own columns are "item.data.header"/"item.data.text"/"item.data.link"/ "item.data.link_label", while "item.files" is the nested "FilesProcessor" output sitting beside "item.data", not inside it. "item.data.text" is the child table's plain "text" column - never RTE-enabled anywhere in this table's TCA - so it is rendered through "f:format.nl2br" rather than "f:format.html": there is no rich-text markup to parse, only line breaks an editor typed to preserve. "item.data.link" is TCA type=link, rendered through "f:link.typolink" the same way "Partials/ContentElement/LinkList.html" renders it for the other three CTypes sharing this child table - see that partial's comment for why a plain "href" would be wrong here. A card without a usable link renders its title and text but no ".theme-card__link" - "link" is not required on this relation's own "overrideChildTca", unlike the other three.
