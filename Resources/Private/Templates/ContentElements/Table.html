"bodytext" is delimited/enclosed text, shaped by "table_caption", "table_delimiter", "table_enclosure", "table_header_position" and "table_tfoot". "TableProcessor" (see "Classes/DataProcessing/TableProcessor.php", wired below in "Configuration/TypoScript/ContentElements.typoscript") does the decoding and the row/column split - splitting a two-level, character-code-delimited structure is not something Fluid can reasonably do - and hands this template a ready-to-render {table.headerRow}/{table.bodyRows}/{table.footerRow}/{table.headerColumn}. Markup follows the "Table" contract in "docs/development/component-library.md": ".theme-table-wrapper" is the scrollable, focusable region ("tabindex=0" + "role=region" + "aria-label", the W3C APG scrollable-region-focusable pattern), ".theme-table" the element itself, ".theme-table__caption" the caption. ""/""/""/"" are styled through plain element selectors under ".theme-table", not a class each. "table_tfoot" is honoured with a real "" - correct semantic HTML needs no class of its own - but note for anyone extending the stylesheet: "components/_table.scss" only documents and styles ""/"", so a footer row currently renders with no component styling beyond what it inherits from ".theme-table" itself. Escaping: "table.caption" and every cell come straight from an editor. Both are output through plain Fluid variable interpolation, which HTML-escapes by default - nothing here uses "f:format.raw" or "f:format.html", so text typed into a cell is shown as text, never executed as markup.
