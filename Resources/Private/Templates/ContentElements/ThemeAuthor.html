"theme_author" - a person: portrait, name, role and links. "header" (the name) goes through the shared "ContentElement/Header" the same as every other element - it is a required field ("Configuration/TCA/Overrides/tt_content_theme_author.php") rendered through the full "headers" palette, so the usual "header_layout" switch applies unchanged. The name is therefore not part of ".theme-author"'s own markup: it is the content element's heading, sitting above the component rather than inside it - see "Resources/Private/Scss/components/_author.scss" for what the component covers instead. "files.0" is the portrait: "image" is the core "tt_content" file field (the same one "ContentElements.typoscript" already resolves for "image"/ "textpic"/"textmedia" via "FilesProcessor"), reused here rather than a field of this extension's own. A record with no portrait renders no ".theme-author__portrait" at all rather than an empty box. "listItems" is "tx_theme_list_items" - here the person's own profile/ contact links, restricted by "overrideChildTca" to "link"/"link_label" only (no "header"/"text"/"image" on this relation, see the TCA file) - resolved the same way "theme_linklist" resolves it (see "Configuration/TypoScript/ContentElements.typoscript") and rendered through the identical ".theme-content-menu"/"ContentElement/LinkList" pair rather than a link-list markup of this component's own.
