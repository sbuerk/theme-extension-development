The styleguide, rendered from the backend layout "styleguide" (Configuration/PageTsConfig/BackendLayouts/Styleguide.tsconfig). It renders the component library directly and ignores whatever an editor placed on the page. That is not a shortcut, it is what was asked for - "a hardcoded TypoScript for that page rendering some FLUIDTEMPLATE files directly without taking content elements on that page into account" - and it is why the layout's only column is the inert colPos 999 that no "lib.content.*" object reads. So there is **no "f:cObject" anywhere in this file or in any of the partials below**, not even for "main". A single one would make the page a content page again, and the difference would only show once somebody happened to drop an element on it. The showcase pages seeded under "/elements" cover the other path - real records, through the real content element rendering. The two are complementary: this page proves the library, those prove the wiring, and a component can be broken in one without the other noticing. One "section" per partial, in the order of the step 7b contract, and the index below is built from the same list. Splitting the sections into their own files is the same rule the rest of the theme follows: a site package that wants its own forms section overrides one file rather than this one. The index reuses ".theme-content-menu" rather than introducing an index component of its own. It is exactly what that component is - a flat list of links - so the alternative would be a second stylesheet rule doing the same job, and rendering it here demonstrates the component as a side effect.
