THE ASIDE IS NOT THE SHELL'S ASIDE "Layouts/Default.html" renders a ".theme-page__aside" for any template that defines the "Aside" section, and "Templates/Page/ContentSidebar.html" is the one that does. This template deliberately does not, although it reads the same colPos 1: that element is the navigation column - fixed width, before the main content in the source order, and carrying the sub navigation and the table of contents through "Partials/Page/Sidebar.html". An article's aside is editorial, has to follow the article in reading order, and carries no navigation at all. So it is an ordinary column of the article grid that happens to be an "aside" element, and the shell's two column rule ":has(.theme-page__aside)" stays out of it. The measure is a modifier on the column rather than a rule on the grid track: the track has to be able to grow into the space the aside does not use, while the text inside it must not - see "layout/_page.scss".
