The login form of EXT:felogin on the form contract of the theme (docs/development/component-library.md, "Forms"), replacing felogin's own "Login/Login" template - see "Configuration/TypoScript/Felogin.typoscript" for how it takes precedence on both core versions. It keeps everything felogin's own template sends: the field names "user", "pass" and "permalogin", the hidden "logintype", "redirect_url", "referer", "redirectReferrer" and "noredirect", the signed request token and "target=_top". Only the markup around them changes. One template serves TYPO3 v12 and v13: the variables it reads are the ones the login action of both assigns, and the labels are full "LLL:" references, which both resolve. The status message felogin assigns as "messageKey" becomes an alert of the kind it is. "error" - a failed login - is the one message about something that just went wrong and takes "role=alert", assertive, on the danger kind; "logout" confirms something finished and takes "role=status" on the success kind. "welcome", the default, is not a message about the page at all but the form's introduction, and stays a heading and a paragraph. The required marker is a sighted-user affordance with aria-hidden; what a screen reader announces is the control's own "required" attribute. The checkbox is a ".theme-check": the input inside its label, so the label is the target, rather than felogin's label before a bare checkbox.

The hidden "0" goes first so the checkbox overrides it when ticked. When permanent login is the default it is disabled - a disabled field is not submitted - and the ticked checkbox alone decides, which is what felogin's own template does.

felogin's "RenderLabelOrMessage" partial, as a section: a label may be overridden by a setting of the same key, and falls back to felogin's own language file. A section rather than a reuse of the partial, so the template reads nothing of felogin's but the variables its controller assigns, whatever felogin's partial root path holds. {settings.{key}}
