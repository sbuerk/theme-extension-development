Sub navigation - the current section, not the whole site. Rendered from "Partials/Page/Sidebar.html", above the "sidebar" content slot, only on the "content_sidebar" backend layout. Markup contract: docs/development/component-library.md#navigation, styled by "components/_nav-sub.scss". "subMenu" comes from core "MenuProcessor", two levels deep, resolved against the current page's first-level ancestor rather than the current page itself - see the step 3 contract for why - so the sidebar keeps showing the section on a third-level page instead of emptying out. Both levels are rendered by one recursive "Item" section, the same reasoning as "Partials/Navigation/Main.html": one set of spacer/current/plain branches, called again for "item.children" instead of being written out twice. Unlike the main navigation there is no "--active" modifier to gate by depth (see the SCSS header comment - "[aria-current='page']" alone is enough wherever it sits in a section-scoped list), so the recursive call needs no extra argument beyond the item itself. Spacers and the "aria-current" omission follow the same reasoning as "Partials/Navigation/Main.html" - see that file's comment. Empty guard: no "subMenu" means no nav element at all, not an empty one.
