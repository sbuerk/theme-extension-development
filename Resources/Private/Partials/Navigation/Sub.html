Sub navigation - the current section, not the whole site. Rendered from "Partials/Page/Sidebar.html", above the "sidebar" content slot, only on the "content_sidebar" backend layout. Markup contract: docs/development/component-library.md#navigation, styled by "components/_nav-sub.scss". "subMenu" comes from core "MenuProcessor", two levels deep, resolved against the current page's first-level ancestor rather than the current page itself - see the step 3 contract for why - so the sidebar keeps showing the section on a third-level page instead of emptying out. Both levels are rendered by one recursive "Item" section, the same reasoning as "Partials/Navigation/Main.html": one set of spacer/current/plain branches, called again for "item.children" instead of being written out twice. Unlike the main navigation there is no "--active" modifier to gate by depth (see the SCSS header comment - "[aria-current='page']" alone is enough wherever it sits in a section-scoped list), so the recursive call needs no extra argument beyond the item itself. Spacers and the "aria-current" omission follow the same reasoning as "Partials/Navigation/Main.html" - see that file's comment. Empty guard: no "subMenu" means no nav element at all, not an empty one. --- A branch is a "details", and there is no script ------------------------ An item with children is wrapped in a native "details"/"summary" pair, so the reader can fold a branch away. The element does all of it: the state, the keyboard handling and the expanded/collapsed semantics a screen reader announces. No script, no "data-js" gate, and nothing degrades - a page whose JavaScript never loads has a working tree, which is why this is built on "details" rather than on a button and a class. THE LINK IS NOT INSIDE THE SUMMARY. It was, in the first version of this: a summary takes phrasing content, its accessible name is its subtree text, and the branch title would have named the disclosure control by itself. axe refuses it - "nested-interactive", serious, on every appearance and palette of the styleguide fixture - because a summary is a widget and a focusable descendant inside one is a control a reader cannot predict. So the branch link and the toggle are siblings: the link is the row, the summary is a square at the end of it, and "components/_nav-sub.scss" lays the two out over the list the summary discloses. THE TOGGLE IS NAMED BY TEXT, NOT BY "aria-label". Its name is a visually hidden span inside it - the naming method a summary actually has - and it names the branch rather than the action: "Pages below Analytics", not "Toggle". An "aria-label" would be an attribute on an element whose role is not the theme's to guess at, and the visible chevron stays decoration. THE BRANCH THE READER IS IN IS OPEN. "open" is written onto the branch holding the current page, which "MenuProcessor" marks "active" (an ancestor) or "current" (the page itself). Every other branch starts folded. The attribute is built as a variable rather than written as "open="{...}"": an "open" attribute is true whatever its value, empty string included, so a conditional value would leave every branch open.
