Main navigation, rendered from "Partials/Page/Header.html" on every page template. Markup contract: docs/development/component-library.md#navigation, styled by "components/_nav-main.scss" - do not add or rename a class here without a rule there. "mainMenu" comes from core "MenuProcessor", two levels deep ("special = directory" plus "expandAll = 1" from the site root, "includeSpacer = 0"). Both levels are rendered by one recursive "Item" section rather than by nesting the list item/link/list markup twice - the section calls itself for "item.children", so the same three branches (spacer, current link, plain link) are written once and apply at every depth the menu ever produces. "id="nav-main"" lives on the top-level list here, outside the recursive section, and nowhere else - it is what the toggle button's "aria-controls" below points at, and the contract needs exactly one element carrying it. The nested "--sub" list never repeats it. --- Active vs. current ----------------------------------------------- "item.active" (an ancestor of the current page) and "item.current" (the current page itself) are independent, per the SCSS header comment: a top-level item can be "--active" while its own link is not "[aria-current='page']" because the current page is one of its children. The "--active" modifier is therefore only ever applied at the top level - "isTopLevel" carries that down through the recursion instead of a level number, since the only thing depth changes here is that one modifier. --- Spacers ------------------------------------------------------------- "mainMenu" is built with "includeSpacer = 0", so none are expected in practice, but "MenuProcessor" still sets "item.spacer" on every item unconditionally, and a site package could change that TypoScript without touching this partial. A spacer is not a link: it renders as a plain span element carrying the same "__link" class for consistent spacing, with no "href" and nothing to focus. --- aria-current is omitted, never emitted empty ------------------------ The two link branches below exist because a whole attribute cannot be switched on or off from inside an already-quoted attribute value without breaking the source XML - one branch carries "aria-current='page'", the other omits it entirely, matching the accessibility contract's "never a modifier class instead" rule without ever emitting "aria-current=''". Empty guard: no "mainMenu" means no nav element at all, not an empty one.
