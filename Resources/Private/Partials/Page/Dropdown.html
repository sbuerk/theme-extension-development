A labelled trigger that discloses a panel under it. Markup contract: "components/_dropdown.scss". Arguments: id the id of the panel. Required, and unique on the page, as any id is: the acceptance suite and a site package addressing one particular dropdown both look the panel up by it. label the text of the trigger. Visually hidden, like the name of the settings cog - the header row has no width for a second piece of visible text - but real text, so it is translated with the page and by a browser's own page translation. icon an icon of the set before the label. Optional. content the markup of the panel, already rendered. "content" is an argument rather than the tag content of the partial, because a partial has no children: "f:render partial" renders the file and discards whatever stands between its tags, and "f:renderChildren" only resolves inside a ViewHelper. The caller renders its panel into a variable and hands it over - see "Partials/Page/Header.html". So the dropdown still knows nothing about what it holds. Caller contract, because this partial escapes neither of them: "id" is written into the panel's "id", and "content" is rendered with "f:format.raw". Both callers are templates of this extension, and both values have to stay that way - "id" a literal the template controls, "content" markup a partial of this extension rendered and escaped on the way in. Neither may ever carry a value that reached the template from a record, a request or an editor. --- The browser opens it --------------------------------------------------- "details" and "summary" are the whole mechanism: the browser opens and closes the panel and announces the expanded state, with no script. That is why this control is rendered unconditionally rather than hidden until "data-js" the way the display settings are. There is no "aria-expanded" here. A "summary" carries the expanded state of its "details" by itself; an authored attribute would be a second copy of it that a script has to keep in step, which is what this component had while the panel was a popover. Why it is no longer one - and what "theme.js" adds instead, namely Escape, a click outside and focus leaving the control - is in the header comment of "components/_dropdown.scss".
