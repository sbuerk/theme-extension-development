The site header, sitewide chrome rendered unconditionally by "Layouts/Default.html" for every page template. This file picks one of four arrangements and renders nothing itself. Each one is a partial below "Page/Header/", the shared pieces are "Brand", "Controls" and "Action" next to them, and "layout/_site-header.scss" carries a modifier per variant. That is the shape the rule about version aware code asks for, applied to a different axis: a difference that changes the whole block is a second file, never a condition sprinkled through one. WHICH ONE IS A SITE SETTING. "theme.header.variant" - declared in "Configuration/Sets/ThemeExtensionDevelopment/settings.definitions.yaml" and, with the same default, as a TypoScript constant in "constants.typoscript" for a site that takes the theme through the classic static include. "Page.typoscript" reads the constant into "headerVariant"; see the comment there for why it is a variable rather than something the template looks up. THE VALUE NEVER BECOMES PART OF A PATH. "f:render partial="Page/Header/ {headerVariant}"" would be shorter and is exactly the shape that turns an editable setting into a file system lookup. The switch names all four partials as literals, so a value nothing matches renders the default one rather than reaching for a file. --- Each arrangement has a width of its own ------------------------------ In all four the main navigation keeps its top level in one row and the title gives way beside it; where one row no longer fits, the navigation collapses behind its toggle. Where that is depends on what shares the menu's row, so each arrangement has a breakpoint of its own, sized for the seven top level entries of the showcase - "bp.$header-*" in "abstracts/_breakpoints.scss", measured and explained in "layout/_site-header.scss". "centred" and "actions" give the navigation a row of its own and hold it down to the narrowest width; "two-tier" shares its row with the title only; "simple" shares it with the title and both controls and collapses first. A new arrangement needs a breakpoint of its own - "ComponentLibraryTest" reads the modifiers from the partials below "Page/Header/" and fails on one that has none.
