The site header, sitewide chrome rendered unconditionally by "Layouts/Default.html" for every page template. Markup contract: docs/development/component-library.md#layout. Main navigation: "Partials/Navigation/Main.html" renders ".theme-nav-main" itself, including its own empty guard, so it is rendered unconditionally here the same way the brand link is - the partial decides whether anything actually appears. ".theme-site-header__actions" is the slot at the end of the header the contract documents; it holds the display settings, "Partials/Page/Settings.html" - one cog button, so the brand and the main navigation keep the width of the row - which is hidden by its own CSS until a script has run - see that partial's header comment.
The language menu, in a dropdown so the header row keeps its width whatever the site's languages are called. The guard counts the languages rather than testing the menu for emptiness. "LanguageMenuProcessor" defaults "special.value" to "auto" and returns early only for a site with no language at all, so a one language site produces a menu of exactly one item - the language already being read. That is a control offering the reader nothing, so the whole dropdown is left out below two languages. The dropdown itself needs no script and is never hidden behind "data-js": the browser opens and closes the popover. See "Partials/Page/Dropdown.html". It sits before the display settings: the language is a property of the page, the settings are a property of the reader.
