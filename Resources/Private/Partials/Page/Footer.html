The site footer, sitewide chrome rendered unconditionally by "Layouts/Default.html" for every page template. The four columns and the meta row are each their own TypoScript object under "lib.content." (see the step 2 contract's "Content slots" table) and each carries "select.slide = -1" - the content lives on the site root and is inherited by every page below it, independent of that page's own backend layout. Each cObject is resolved once into a variable rather than called directly inside an "f:if" condition and again inside its body: "f:cObject" runs a TypoScript CONTENT object, and calling it twice would render it twice. The variable also gives requirement 3 something to check the truthiness of - an empty string is falsy in Fluid, so a column with nothing on the site root (or between the current page and the root) does not get an empty ".theme-site-footer__column" wrapper. An empty wrapper would still be a cell in ".theme-site-footer__columns"'s auto-fit grid, which is exactly the same defect this file's comment on the aside warns about. "f:format.raw" is required on the way back out: "f:cObject" itself does not escape its return value, but that only holds while its own node is still in the syntax tree. Once the value has been captured into a plain Fluid variable it is just a string again, and "{footer1}" without "f:format.raw" would HTML-escape the markup CONTENT already rendered.
{footer1 -> f:format.raw()}
{footer2 -> f:format.raw()}
{footer3 -> f:format.raw()}
{footer4 -> f:format.raw()}
{footermeta -> f:format.raw()}
