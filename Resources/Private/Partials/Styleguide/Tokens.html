Section D5 of the step 7b contract: the token section. Every swatch, type sample and spacing bar below reads its value through "var()" in a "style" attribute. That is the one place on this page where an inline style is correct - the value being demonstrated *is* the token, and a class per token would mean a stylesheet rule per token in "layout/_styleguide.scss" that carries no information the attribute does not already carry. The colour groups and their order follow "Resources/Private/Scss/abstracts/_tokens.scss" - neutrals (lines 84-95), accents (100-105), semantic (113-134) - so a token added there has an obvious place here. All 27 "--theme-color-*" tokens declared in that file have a swatch; assertion 5 of the contract derives that list from the SCSS rather than from a list here, so an omission fails a test rather than passing review. Specimen copy is literal English, per contract D3: it exists to be set in a typeface, and there is nothing in it to translate. Two things are deliberately *not* demonstrated here, because they have no visual form on a static page: the motion tokens (a duration and an easing curve, "_tokens.scss" 191-194) and the stacking tokens ("_tokens.scss" 182-189), which are only meaningful between two overlapping elements.

Tokens

The design tokens are the theme's public API for a site package: every value in the stylesheet comes from one of them, and a site can re-theme the extension by overriding a handful of custom properties without rebuilding the SCSS. This section is also a live test of the appearance and palette switchers in the page header — flip either one and every swatch below has to move together, because a swatch that does not is a token that was declared outside light-dark().

Colour — neutrals

Shared by every palette. A palette varies accents only, which is what keeps a palette to a single block.

Colour — semantic

Three tokens per meaning, because one colour cannot do all three jobs: the accent is a text and border colour, on-* is the foreground for a solid fill of it, and *-surface is the soft tint an alert or a badge sits on. The info group aliases the primary accent rather than introducing a fifth hue, so it follows the palette along with the accents above.

Weight and family

Three weights, with no 600 or 700 between them — a system font may synthesise 800 or clamp it to its boldest weight. Neither family token loads a webfont: the extension ships none and makes no external request, so both resolve to a system stack.

Regular — running text, and the weight of the body role.

--theme-font-weight-regular — 400

Medium — labels, controls and the third heading level.

--theme-font-weight-medium — 500

Bold — the display size and the first two heading levels.

--theme-font-weight-bold — 800

The sans stack carries everything except code.

--theme-font-family-sans

The mono stack carries code, keys and sample output.

--theme-font-family-mono

Spacing scale

A 5px grid, measured from the auto-layout gaps of the reference design and expressed in rem, so spacing grows when a reader enlarges the base font size. Step 0 is a real token and draws nothing, which is the point of it.

Radius

The reference design has exactly two radii — 5px and a pill — so md is the single extrapolation, kept on the 5px grid. In px rather than rem: a corner should not grow with the root font size. The border below is --theme-border-width, 1px, against --theme-border-width-strong at 2px.

--theme-radius-none — 0
--theme-radius-sm — 5px, the system radius
--theme-radius-md — 10px
--theme-radius-full — 9999px, a pill

Shadow

There is nothing to show here, and that is the specimen: the design is flat and the theme declares no elevation token at all. The reference design contains zero visible effects, so adding one would be a design decision without a source. A component separates itself with a surface fill and a hairline border, as below. The single exception is the focus ring, which is a requirement rather than decoration.

no elevation token — fill and hairline instead

Focus ring

The ring is split in two because light-dark() takes colours and not shadows: a colour token carries both appearances, and the composite is built around it so a site package can still replace the whole ring in one declaration. A palette overrides the colour half, so the ring follows the accent — switch the palette and both boxes below move with it. What you see when tabbing through this page is the same composite, applied through :focus-visible.

--theme-focus-ring-color
--theme-focus-ring — 0 0 0 3px of it
