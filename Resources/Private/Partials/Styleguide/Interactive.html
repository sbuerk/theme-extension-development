Styleguide section "Interactive": the three components of the library that need "Resources/Public/JavaScript/theme.js" - tabs, the dialog and the tooltip - each with what it does when the script never runs. The rules of every other section apply: literal markup copied from the markup contract in the component's own SCSS header comment, nothing driven by a record, a data processor or an "f:cObject", and literal English copy. Ids are prefixed "sg-tabs-", "sg-dialog-" and "sg-tooltip-" so they cannot collide with the page chrome or with another section. "Tests/Acceptance/styleguide.spec.ts" drives these specimens in a browser: the arrow keys on the tabs, the dialog opening as a modal and giving focus back, Escape on the tooltip, and the page loaded with JavaScript switched off and once with "theme.js" blocked. It finds them by the ids and the labels below, so changing one of those is a change to that spec as well. Three deliberate departures from the header comments: 1. The panel headings of the tabs are "h4", for the outline reason given in "Boxes.html": the page already owns h1 to h3. 2. The dialog's title is "h2". A modal dialog is read on its own while the page behind it is inert, and a closed one is not rendered at all, so it starts its own outline rather than continuing this one. 3. The still picture of the dialog carries its title on a "p", because it is a picture of the component rather than a dialog, and a heading in it would add a stray level to the page outline. The stage around it is "inert" for the same reason: its buttons are part of the picture, and inert takes them out of the tab sequence and out of the accessibility tree.

Interactive

The three components in this section are the only ones in the library that need the theme's script. Each one says what it does without it, and this page is the place to check that claim: switch JavaScript off in the browser and reload.

Tabs

Contract: Resources/Private/Scss/components/_tabs.scss. The first tab is the selected one, the other two carry tabindex=-1, and a panel carries nothing but its class and its id - no "hidden", no role, no label and no tab stop; the script adds those three when it binds the group. The three rules that contract states.

The tabs pattern of the WAI-ARIA authoring practices, with automatic activation: the arrow keys move between the tabs and show each panel on the way, Home and End jump to the first and the last tab, and Tab leaves the list straight for the panel, because only the selected tab is in the tab sequence. Without the script there are no tabs to press: the list is not rendered, every panel is shown in a frame of its own, and the heading each panel repeats is what labels it. That holds with JavaScript switched on, too, whenever the theme's script fails to load: the tabs appear only once it has bound the group.

Site set

A site depends on the theme's site set in its configuration, and constants, page TSconfig and setup arrive together. This is the first panel, the one the markup selects.

Static include

An installation without site sets includes the static TypoScript in a template record instead: the same files, read the same way. No panel carries the hidden attribute in the markup, nor a role or a tab stop. The script adds all of them when it binds the group.

Dialog

Contract: Resources/Private/Scss/components/_dialog.scss. The close button and "Cancel" both carry value=cancel, so "returnValue" cannot tell them apart - which is what that contract asks for - and "Cancel" carries "autofocus", so the dialog opens on the action that does no harm.

A native dialog, opened as a modal: the browser keeps focus inside it, makes the page behind it inert and draws the scrim, and the form around its content closes it again with no script. Opening it is the one step that needs the script, so without JavaScript the button below is not rendered and the dialog stays closed — a dialog is for content the page can do without. It opens with focus on Cancel, the action that does no harm when Enter is pressed by reflex. It is flat like every other component: the scrim and a strong border set it apart, not a shadow.

Opens the dialog as a modal. Escape, the close button, Cancel and a click on the scrim all close it again and put focus back on this button - a drag from the text out onto the scrim does not. Nothing is reseeded either way.

Tooltip

Contract: Resources/Private/Scss/components/_tooltip.scss. Two triggers, an icon button and a link, because the bubble has to work on anything focusable. Each bubble opens from its own trigger's inline start edge towards the inline end, so on a phone both stay inside the viewport - the acceptance spec checks that at 400px.

A short description of a control that already has a name. It shows on hover and on focus with no script at all, goes again when focus leaves, and the trigger points at it with aria-describedby, which is what a screen reader announces whether the bubble is on screen or not. Escape hides it without moving focus — the one part that needs the script. The pointer can move onto the bubble to read it without closing it.
