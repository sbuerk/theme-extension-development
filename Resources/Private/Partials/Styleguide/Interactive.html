Styleguide section "Interactive": the six components of the library that need "Resources/Public/JavaScript/theme.js" - tabs, the dialog, the carousel, the lightbox, the external media embed and the tooltip - each with what it does when the script never runs. The carousel is the one of the six that needs the script least: only its two buttons do, and everything else about it works without one. The rules of every other section apply: literal markup copied from the markup contract in the component's own SCSS header comment, nothing driven by a record, a data processor or an "f:cObject", and literal English copy. Ids are prefixed "sg-tabs-", "sg-dialog-" and "sg-tooltip-" so they cannot collide with the page chrome or with another section. "Tests/Acceptance/styleguide.spec.ts" drives these specimens in a browser: the arrow keys on the tabs, the dialog opening as a modal and giving focus back, Escape on the tooltip, and the page loaded with JavaScript switched off and once with "theme.js" blocked. It finds them by the ids and the labels below, so changing one of those is a change to that spec as well. Three deliberate departures from the header comments: 1. The panel headings of the tabs are "h4", for the outline reason given in "Boxes.html": the page already owns h1 to h3. 2. The dialog's title is "h2". A modal dialog is read on its own while the page behind it is inert, and a closed one is not rendered at all, so it starts its own outline rather than continuing this one. 3. The still picture of the dialog carries its title on a "p", because it is a picture of the component rather than a dialog, and a heading in it would add a stray level to the page outline. The stage around it is "inert" for the same reason: its buttons are part of the picture, and inert takes them out of the tab sequence and out of the accessibility tree.

Interactive

The six components in this section are the only ones in the library that need the theme's script. Each one says what it does without it, and this page is the place to check that claim: switch JavaScript off in the browser and reload.

Tabs

Contract: Resources/Private/Scss/components/_tabs.scss. The first tab is the selected one, the other two carry tabindex=-1, and a panel carries nothing but its class and its id - no "hidden", no role, no label and no tab stop; the script adds those three when it binds the group. The three rules that contract states.

The tabs pattern of the WAI-ARIA authoring practices, with automatic activation: the arrow keys move between the tabs and show each panel on the way, Home and End jump to the first and the last tab, and Tab leaves the list straight for the panel, because only the selected tab is in the tab sequence. Without the script there are no tabs to press: the list is not rendered, every panel is shown in a frame of its own, and the heading each panel repeats is what labels it. That holds with JavaScript switched on, too, whenever the theme's script fails to load: the tabs appear only once it has bound the group.

Site set

A site depends on the theme's site set in its configuration, and constants, page TSconfig and setup arrive together. This is the first panel, the one the markup selects.

Static include

An installation without site sets includes the static TypoScript in a template record instead: the same files, read the same way. No panel carries the hidden attribute in the markup, nor a role or a tab stop. The script adds all of them when it binds the group.

Legacy tree

The mirror below /legacy/ renders the showcase through a template record, so the two delivery paths can be compared page by page. This is the last tab: End jumps here, and the arrow key past it wraps round to the first.

Dialog

Contract: Resources/Private/Scss/components/_dialog.scss. The close button and "Cancel" both carry value=cancel, so "returnValue" cannot tell them apart - which is what that contract asks for - and "Cancel" carries "autofocus", so the dialog opens on the action that does no harm.

A native dialog, opened as a modal: the browser keeps focus inside it, makes the page behind it inert and draws the scrim, and the form around its content closes it again with no script. Opening it is the one step that needs the script, so without JavaScript the button below is not rendered and the dialog stays closed — a dialog is for content the page can do without. It opens with focus on Cancel, the action that does no harm when Enter is pressed by reflex. It is flat like every other component: the scrim and a strong border set it apart, not a shadow.

Opens the dialog as a modal. Escape, the close button, Cancel and a click on the scrim all close it again and put focus back on this button - a drag from the text out onto the scrim does not. Nothing is reseeded either way.

Carousel

Contract: Resources/Private/Scss/components/_carousel.scss. The ids are prefixed "sg-carousel-" like every other id in this section. The indicators are links to those ids, which is what makes them work with no script; only the two buttons are gated on the script's own "data-theme-carousel-bound".

Slides in one track that scrolls sideways and snaps. Nothing moves on its own — there is no autoplay, which is how WCAG 2.2.2 is satisfied: there is no motion to pause. Without the script the track still scrolls by touch, trackpad, wheel and scroll bar, and by the arrow keys once it has focus, and the indicators below are ordinary links to the slides, so every slide stays reachable. The previous and next buttons are the one part that needs the script, so they are not rendered until it has bound this carousel. The caption of a slide sits below the picture, above it, or over its foot.

Lightbox

Contract: Resources/Private/Scss/components/_lightbox.scss. A still picture, for the reason the dialog above has one: a closed dialog renders nothing and an open one covers the page. The stage is "inert", so the buttons in it are part of the picture. The markup here shows one item, because that is what the lightbox looks like on screen. In the page the dialog carries one figure per image of its gallery and the script hides all but the one that was opened - the markup hides nothing, per the contract.

The enlarged image of a gallery, in a dialog. It is the same component as above - the box, the scrim, the header and the footer are the dialog's - widened for a picture, and its header carries no title: an image has a caption, which is inside the picture and changes with it.

The opener is the zoom link of the gallery, which keeps its href to the file. That is why it is not a data-theme-dialog-open opener: the stylesheet hides those without a script, and a link that enlarges the image on its own must not be hidden. The arrows move within the gallery and wrap at both ends, the arrow keys do the same, Escape closes, and focus returns to the thumbnail that was pressed.

The working lightbox is on the seeded showcase page of the image element, where there are real files to enlarge. Here it is a picture: the scrim below is the stage, not a modal.

Privacy friendly embed

Contract: Resources/Private/Scss/components/_embed.scss. **Neither specimen is wired to a provider.** A specimen carrying a real "data-theme-embed-src" would be bound by "theme.js" on this page, and pressing it would load a video from another site into the styleguide - which contract D2 rules out and which is the one thing this component exists to avoid. The working element is on the seeded showcase page, and "Tests/Acceptance/elements.spec.ts" drives it there. So the first specimen is the component as a page without the script shows it, and the second carries "data-theme-embed-bound" by hand - the marker "theme.js" sets - to show what the bound state looks like. Both are "inert": their buttons are part of a picture.

A video of another site, which is not loaded until the reader asks for it. The page carries a poster and a button, and only a press on the button puts an iframe in the frame - so opening a page opens no connection to the video's host, and a reader who never watches the video leaves no trace with it.

The button follows the marker the script sets on the component, not the one the inline head script sets on the page. The difference matters here: with the script merely announced but never loaded, a button gated on the page marker would be a play button that does nothing, over a video nothing else offers a way to.

Without the script: the poster, the note and the link to the source - which is the whole of the component, and enough to watch the video.

With the script: the same component, carrying the marker the script sets once it has bound the button.

Tooltip

Contract: Resources/Private/Scss/components/_tooltip.scss. Two triggers, an icon button and a link, because the bubble has to work on anything focusable. Each bubble opens from its own trigger's inline start edge towards the inline end, so on a phone both stay inside the viewport - the acceptance spec checks that at 400px.

A short description of a control that already has a name. It shows on hover and on focus with no script at all, goes again when focus leaves, and the trigger points at it with aria-describedby, which is what a screen reader announces whether the bubble is on screen or not. Escape hides it without moving focus — the one part that needs the script. The pointer can move onto the bubble to read it without closing it.
