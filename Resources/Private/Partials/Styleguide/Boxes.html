Styleguide section D1 "Boxes": the box shaped content components of the library - card, panel, teaser, hero, quote, alert, accordion, author - each with every modifier its own SCSS file defines, not only the ones a content element happens to use. Every specimen is literal markup taken from the component's own SCSS header comment, which is the authoritative contract. Nothing here is driven by a record, a data processor or a TypoScript object (contract D2), and the copy is literal English rather than a translated label (contract D3): a specimen paragraph exists to be set in a typeface and describe the component it sits in, and has no meaning to localise. Three deliberate, documented departures from the header comments, each also noted at the specimen it applies to: 1. Heading level. "_card.scss" illustrates its title as "h3", "_teaser.scss" as "h2" and "_hero.scss" as "h1". Every specimen on this page already sits below the page "h1", the section "h2" and the component "h3", so those levels would restart the outline in the middle of the page. The stylesheets select the titles by class and never by tag - which is exactly why "Partials/ContentElement/Hero.html" can switch h1..h5 on the same class from "header_layout" - so "h4" renders identically and keeps the document outline intact. 2. The "role" on the alert. The contract illustrates "role=status" on a "--warning" alert; the four severities do not all take the same role. See the comment at that specimen. 3. Media. There is no image a Fluid partial can reference without a FAL record, so the two variables below carry an inline SVG data URI. An "img" element - not a styled placeholder box - because the rules under "theme-card__media", "theme-teaser__media", "theme-hero__media" and "theme-author__portrait" all select "img" (object-fit, the circular portrait mask, the full bleed to the frame edge); a substitute element would leave every one of them undemonstrated. Quotes inside the URI are written "%27" rather than literally so the value is unambiguous whether Fluid escapes it or not, and no byte of it leaves the page: the theme must render with no network. Its two colours are hard coded and do not follow the appearance setting. A data URI in an "img" is an isolated document and inherits no custom property, so it could not - but it should not either: a photograph an editor uploads does not repaint in dark mode either, and a placeholder that did would demonstrate something the component never does. The two values are the light-mode fallbacks of "--theme-color-border" and "--theme-color-text-secondary", so the stand-in reads as part of the palette in the appearance the theme starts in.

Panel

Contract: Resources/Private/Scss/components/_panel.scss. No modifiers. Header, aside and footer are optional, which is why the second specimen carries a body and nothing else. The first panel is a "section" labelled by its title, which makes it a region landmark; the second is a "div", the shape the contract gives a panel that is not a destination of its own. The title is "h4" for the outline reason at the top of this file. It sits directly after the card on purpose: the two look related, and the comparison is what says they are not the same component.

Panel, with every part

Seeded

Grouped content that lives here, rather than a teaser for content that lives somewhere else: a status block, a set of settings, a summary with actions of its own. The header is the one tinted part, and the badge opposite the title wraps under it when the row runs out of room.

A panel with a body and nothing else is still a panel: a hairline frame on the raised surface, with no media slot, and no link stretched over the whole box the way a linked card has one.

Teaser

Contract: Resources/Private/Scss/components/_teaser.scss. One modifier, "--reversed". Both specimens keep the media before the body in source order, which is the point that file makes at length: "row-reverse" changes paint order only, so the reading and focus order are identical in the two variants. "theme-teaser__link" is the component's own text link. The theme's content elements render their call to action as a ".theme-button" instead (see Partials/ContentElement/Teaser.html), which is why this class has no other demonstration anywhere.

Teaser, the bare class

Media beside body from 48rem upwards, stacked below it. The media keeps 42% of the row and the body takes the rest, and the image is stretched to the full height of whichever of the two turns out taller.

The teaser's own text link

Teaser, the modifier --reversed

The media moves to the trailing side once the row layout applies. The markup is unchanged - the media element still comes first in source - so a screen reader announces both variants in the same order, and the only focusable element in either one stays where it is.

Quote

No modifiers in that file, and no media slot either - see the comment in Templates/ContentElements/ThemeTestimonial.html for why the image field was taken off that CType again rather than left to collect portraits the component cannot show. Alert

Contract: Resources/Private/Scss/components/_alert.scss. Modifiers: "--info" (also the appearance of the bare class), "--success", "--warning", "--danger". The "role" is fixed by that contract and is a markup concern the stylesheet does not touch - which is exactly why it is decided here and not copied uniformly off the illustration. The illustration in the SCSS header shows "role=status" on a "--warning" alert; the four severities do not share one role. "status" is a polite live region and fits an informational or confirming message; "alert" is an assertive one and is what a warning or an error needs, because an assistive technology should interrupt for those two and not for the other two. Info and success therefore take "status", warning and danger take "alert". Nothing on this page is announced either way - a live region speaks when its content changes, and these are static - so what is demonstrated here is the markup an integrator copies, not a behaviour. The stylesheet is explicit that colour is not the only signal: the icon slot carries a distinct icon per kind, and that icon is what communicates it to a reader who cannot tell the tints apart. The six are the ones "Partials/ContentElement/AlertIcon.html" maps the kinds to, which is what a notice and a login message render. They fill with "currentColor" from the slot, which the stylesheet paints with the accent of the kind.

Info, and the bare class

The neutral severity, and what ".theme-alert" looks like with no modifier at all. The modifier is listed in the stylesheet anyway, so a template can name it rather than rely on the default.

Success

Confirms that something finished. Polite like the info variant: it is worth reading, and worth nobody's attention being taken away from what they were doing.

Warning

Something needs attention before it becomes a problem. Note that the body text keeps the same colour in all four variants: it was contrast checked once against every tint, and re-deriving it per severity would reopen a check already settled.

Danger

Something failed or is about to. The four variants differ in nothing but the tint, the leading border and the icon accent - which is why each of them carries its own glyph rather than one shared symbol.

The two asides, "--note" and "--tip", after the four severities. Neither is a message about the page, so neither is a live region: both take "role=note", as the contract in "_alert.scss" states. The tip is the one kind that follows the palette - switch the palette in the header and its tint and accent move while every other alert stays as it is.

Note

An aside to the text around it rather than a message about the page, on the surface panels already sit on, with the secondary ink as its accent. It takes the note role and not a live region, because nothing about it ever changes.

Tip

A recommendation, and the one kind that follows the palette: its accent is the palette's secondary, and its tint is mixed from that accent in the stylesheet. Switch the palette in the header and this is the only alert that changes colour.

Accordion

Contract: Resources/Private/Scss/components/_accordion.scss. No modifiers in that file; the one state it styles is "[open]", which is why the first item below is open - it is the only way to see the chevron flipped. The shared "name" is the component's whole behaviour: the browser closes the other items when one opens, which is what a hand-rolled accordion normally reaches for JavaScript to do. The value has to be unique on the rendered page, because two groups sharing a name would close each other's items; "theme-styleguide-boxes-accordion" names the page, the section and the component, so nothing the chrome or another styleguide section renders can collide with it.
What makes these three mutually exclusive?
The shared "name" attribute on every "details" element in the group. Open either of the two below and this one closes on its own, with no script involved.
Where does the chevron come from?
From the icon set of the theme: it is the chevron-down icon, the last thing in the summary. Opening an item turns it half a turn, so there is no second icon to keep in sync with the open state.
What does the stylesheet actually do here?
It places and turns the marker and gives the summary a tap target floor, and that is all. Toggle state, keyboard handling and the expanded/collapsed semantics an assistive technology reads all come from the element itself.

Author

Contract: Resources/Private/Scss/components/_author.scss. No modifiers in that file. The person's name is deliberately outside ".theme-author": it is the content element's own heading, rendered through the shared Partials/ContentElement/Header the same as every other element, so it sits above the component rather than inside it. The heading below stands in for it, at the level this page's outline needs, so that the relationship is visible rather than merely described. The links are ".theme-content-menu", the component the three link list CTypes already use - see Partials/ContentElement/LinkList.html for why this component does not ship a link list of its own. The "nav" is a landmark, so it is labelled as a specimen: the page carries real navigation landmarks too, and two identically named ones would be offered side by side in a screen reader's landmark list.
