There is no image this partial could reference: a real gallery image comes out of a "sys_file_reference" through "f:image", and a styleguide specimen has no record - that is the whole point of contract D2. A remote URL is out because the theme has to render with no network at all. A styled placeholder box was the alternative and was rejected: it would have to be a "div", and the contract puts ".theme-gallery__image" on an "img" whose "width"/"height" attributes are what reserves the box before the image loads. A specimen that swaps the element out stops demonstrating the component. The data URI keeps the real "img", the real attributes and the real intrinsic ratio, and costs one long attribute value. --- Escaping ----------------------------------------------------------- Curly braces in specimen copy are written "{" / "}". Fluid's parser splits on the literal "{" character (Core/Parser/Patterns.php, "$SPLIT_PATTERN_SHORTHANDSYNTAX", line 109) and that pattern has no backslash-escape branch, so prefixing an opening brace with a backslash leaves it a brace and the term is still read as an object accessor, which renders empty. The entity contains no brace character at all and is decoded by the browser, not by Fluid.

Media

Gallery, one column

The gallery is what the image and text-with-media content elements render. Core's GalleryProcessor has already decided the column count and the width of every image, so the stylesheet lays the row out and imposes no count of its own - the editor's "Number of columns" field would otherwise stop meaning anything. The count travels as the data-theme-gallery-columns attribute for CSS that wants to react to it.

Both position modifiers are on the wrapper. The vertical one comes from the same field as the horizontal one - "above", "intext" or "below". "above" and "below" are the order of the markup; "intext" becomes a float, shown further down. Every item is a .theme-figure as well.

Gallery, two columns, left

Two rows of two. The row is a wrapping flex line, so a count that does not divide the file count evenly leaves a short last row - which is what the alignment modifier then acts on.

Gallery, three columns, right, with zoom links

The zoom wrapper is what the editor's "Enlarge on click" field produces. It is a plain link to the original file: a lightbox is JavaScript, and this extension ships none.

Gallery in text

What "Partials/ContentElement/Gallery.html" renders for "In text, left": the processor's two positions, and the float they translate to. The paragraph after it stands in for the element's bodytext.

"In text, left" of a text-with-image element. The partial adds --float-start to the two positions the processor reports, and the whole gallery floats to the start of the line - the right side of it in a right-to-left page - capped at half the column. Below the medium breakpoint it does not float at all, and the text follows it.

Whatever holds a floated gallery becomes a block formatting context and contains it, so a text shorter than the image does not leave the image hanging into the next element. "In text, no wrap" adds --nowrap, and the text beside the gallery then stays beside it instead of flowing back under it.

Figure

Contract: Resources/Private/Scss/components/_figure.scss.

.theme-figure is a figure outside a gallery - in rich text or a template. The caption starts at the inline edge, or ends there with --caption-end, and an optional credit line closes it, one step quieter.

Figure floated in running text

--float-start and --float-end float a figure to that side of the text around it from the medium breakpoint up, capped at half the column; below it the figure takes the full width, because text beside a half-width image on a phone is a column of three words. The float is logical: the start is the right side of a right-to-left line.

The text wraps around the figure and continues under it once it is past. This paragraph is long enough to do that at the width of the styleguide, so the two lines of it that end below the image run the full width of the frame again.

A figure floated to the end sits on the other side. The frame this specimen is drawn in contains both floats by itself - a block that holds a floated figure as a direct child becomes a block formatting context - so the image never hangs out of the bottom of it.

Content element wrapper

Every rendered content element goes through this wrapper. The --{CType} modifier and the data-ctype attribute both carry the CType: the modifier is the styling hook, the attribute is what the dashed frame prints as its label, through content: attr(data-ctype).

This is the affordance that made "Frame" the chosen structural variant. The theme exists so other extensions can be developed against it, and a visible element boundary is what turns "my element renders wrong" into something you can see instead of something you have to infer. It is a development and staging aid, not a permanent part of a production page.

Two wrappers follow each other here, because the spacing between content elements is read from the following element rather than from its predecessor - a modifier on one element can then never leak into its neighbour.

A text element. The frame is drawn as an outline rather than a border, so switching it off never reflows the content beside it.

A text-with-media element. Its chip reads "textmedia" because that is the value of its data-ctype attribute, not because anything was written into the markup twice.

Content element wrapper, outline switched off

The documented global switch is one attribute on the root element: <html data-theme-content-outline="off">. The theme's own TypoScript sets it from a setting, so an integrator normally never writes it by hand. It takes the CType chip with it as well as the outline - a switch that removed only the outline would leave a stray chip floating on a production page.

A Fluid partial cannot set an attribute on <html>, so the pair below sets it on a wrapping div instead. That is not a simulation: the rule is written as a descendant selector, so the attribute switches off every .theme-content-element below whichever element carries it. The root element is simply the ancestor that reaches all of them at once. Set the attribute on a single column and only that column loses its frames.

Left, unchanged; right, inside a wrapper carrying the attribute.

Outline on. This is the default, and the chip reads "header".

Outline off. Identical markup on the element itself - the attribute is on the wrapper around it. No outline, and no chip either.

Content element bands

The frame of a content element, chosen in its "Appearance" tab: --frame-surface, --frame-raised, --frame-accent and --frame-inverse fill the element and draw the hairline around it. The development outline sits on top of that hairline and goes with the global switch as before; the band stays.

The inverse band re-points no colour of its own. It turns the colour scheme of everything inside it, so the link and the buttons in it are the ones of the other appearance - each as readable as it is on a page in that appearance.
