Typography

Headings

All six heading levels share one rule: a tracking that opens the letters up - the one place this design tracks out rather than in - and text-wrap: balance, so a heading that wraps does not leave a two-word orphan on the last line. Down to level three the size carries the level. Levels four to six reach the body size and the two steps below it, so size cannot separate them from the text around them: level four is the body size at weight 800, levels five and six are set in capitals with a wider tracking, and level six is in secondary ink. The six samples below are marked as presentational, so they demonstrate the type without adding themselves to this page's heading outline.

Running text

Body copy is set at 16 pixels with a line height of 1.6 and no letter spacing at all. The zero is written out as a token rather than left to the browser default, because letter spacing inherits: a paragraph sitting inside a heading-tracked ancestor would otherwise pick that tracking up by accident and read as slightly wrong without anybody being able to say why. Line length is held by the page frame, not by this paragraph, so the measure you see here is the measure an editor gets.

A second paragraph makes the vertical rhythm visible: every prose block in the baseline ends with the same 20 pixel bottom margin and has no top margin, so the gap between two blocks is one value and never the sum of two. Paragraphs wrap with text-wrap: pretty, which keeps a single word from ending up alone on the last line.

Long unbroken strings wrap instead of widening the page. A URL such as https://docs.typo3.org/permalink/t3coreapi:frontend-typoscript-typoscript breaks mid-token rather than pushing a horizontal scrollbar onto the whole document; a linked one, such as https://docs.typo3.org/permalink/t3coreapi:frontend-typoscript-typoscript, also stops asking its container for its full width, and the wbr elements after each slash give it the break points a reader expects.

Inline elements

Inline semantics carry meaning, so each one is given a treatment that survives without colour: strong is bold at weight 800 and emphasis is italic, while small drops to 12 pixels in secondary ink for the caption role. A marked passage takes the warning surface tint, and a revision reads as a diff, with deleted text struck through next to inserted text underlined - the line, not the colour, is what carries it.

Scientific and technical notation is covered as well: water is H2O, an area is measured in m2, and an RTE abbreviation is marked by a dotted underline rather than a box, because a box already means a cell or a badge here. Press Ctrl + K to insert a link, which takes the primary colour and shifts to the hover colour on pointer over. A key combination is one kbd holding one per key - Ctrl+Shift+P - and only the keys are framed. A shell answers Nothing to commit, working tree clean, an identifier such as maxWidth is italic, and --theme-font-size-md is set in the mono family on the surface tint.

A design token is a named value a component reads instead of a literal - the defining instance of a term is italic and a step heavier, so it does not read as plain emphasis.

Quotation marks are set explicitly rather than left to the browser, which picks a different pair per engine: an outer quotation contains an inner one and both marks are this theme's own. The language of the quotation still decides which pair: ein deutsches Zitat mit innerem Zitat, une citation française avec une citation intérieure. A date such as 16 August 2026 is set in tabular figures, so a column of dated items lines up.

Lists

Unordered and ordered lists share one indent of 40 pixels and one item gap of 5 pixels. A nested list is the case worth checking: it sits inside a list item that already carries that item's own bottom margin, so it drops its own and the gap before the first nested item stays a single value.

  • A top level item in an unordered list.
  • An item that carries a nested list of its own:
    • The first nested item, one indent further in.
    • The second nested item, at the same depth.
  • The last item, whose bottom margin is removed.
  1. Ordered lists take the same indent as unordered ones.
  2. The marker is the browser's own; no counter is redefined.
  3. Numbering is what distinguishes them, not spacing.
Definition term
A description is indented by the same 40 pixels as a list item and set in secondary ink, so a definition list and a bullet list read as the same kind of thing side by side.
Second term
Terms are bold, and every term after the first gains a top margin so the pairs do not run together.

Quotations

A block quotation is marked by a two pixel rule on the inline start edge and secondary ink, never by italics: the quoted text may well contain emphasis of its own, and that has to stay visible.

A quotation without an attribution is still a block quotation, and it has to look right on its own, because that is what an editor most often produces.

Preformatted text and code blocks

A code block is data, not prose. Letting it wrap would silently reindent or reflow it, which changes what it says, so it scrolls its own overflow instead of widening the page. Inline code inside a block loses the highlight it carries in running text, because there it is the block's own text rather than a term picked out of it.

Horizontal rule

A rule is one border width tall and drawn as a background colour rather than a border, so it cannot inherit a browser's inset shading. It takes 30 pixels of space above and below, more than a paragraph, because it separates passages rather than lines.

The text after the rule sits at the same distance from it as the text before, which is the point of setting one value for both.

Divider with a label, and a section break

Contract: Resources/Private/Scss/components/_divider.scss. A separator's children are presentational, so its name is the "aria-label", which repeats the visible label.

An hr cannot hold a label, so a labelled separator is a div with the separator role, named by aria-label. The label sits in the middle, or at the start with --start.
