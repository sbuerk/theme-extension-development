Navigation

Main navigation

Two levels deep. The ancestor modifier and the current-page attribute are independent and are shown separately: “Products” is an ancestor of the current page, so its item carries theme-nav-main__item--active while its own link carries no aria-current; “Contact” is the current page itself, so its link carries aria-current="page" while its item carries no modifier. The nested list is the --sub variant, inline below the breakpoint and a floating panel above it.

The toggle is a working control, not a picture of one. It only becomes visible below 48rem, and only once the theme's script has set data-js on the root element — collapsing is an enhancement, so the open layout is what a reader without JavaScript gets. Narrow the window to reach it.

This specimen is the reason the script binds every toggle rather than the first one it finds. The collapse rule matches any .theme-nav-main whose own toggle is not expanded, so a second navigation on a page — this one, or a menu a site package repeats in its footer — would otherwise be folded shut below the breakpoint by a button that was never wired up.

Sub navigation

The current section rather than the whole site: vertical, no breakpoint and no toggle over the block as a whole. There is no --active modifier either — the list is scoped to one section, so aria-current="page" alone marks the current page wherever it sits, here on a second-level item. The heading is a <p>, not an <hN>: the section title above the block already carries the real heading.

An item that has children is a branch: its link keeps the row and a native <details> puts a toggle at the end of it, over the list that toggle discloses. That is the whole of it — the element carries the state, the keyboard handling and the expanded and collapsed semantics, so the tree folds on a page whose JavaScript never arrived. The toggle is named by a visually hidden span naming the branch, not by an aria-label, because subtree text is the naming method a <summary> has. The branch link is deliberately not inside the summary: axe reports a focusable descendant of a summary as a nested interactive control. The branch holding the current page is open, every other one starts folded — below, “Analytics” is open and “Support” is not.

Breadcrumb

An <ol>, because the trail is ordered — root first, current page last — and that order is part of its meaning. The last item is plain text carrying aria-current="page" on the list item itself: a breadcrumb does not still point at the page the reader is on. The / between items is generated content on a ::before, so it is never read out and needs no aria-hidden.

Pagination

No modifier classes anywhere: the current page is aria-current="page" on the link, and the stylesheet targets that attribute rather than a class, so the visual state and the accessible state cannot disagree. The previous and next controls are labelled with aria-label because their glyphs carry no accessible name, and the gap in the sequence is a __ellipsis span — not a link, but sized to match the squares it sits between.

Language menu

One entry per language of the site. The language being read carries aria-current="true" — not "page", since it is this page rather than another one — and is set in the medium weight. A language the current page has no translation for is rendered as plain text with aria-disabled="true": hiding it would say the site has fewer languages than it has, and linking it would promise a translation that does not exist. Each entry carries its own lang and hreflang, so “Deutsch” is announced in German whatever language the page around it is in.

Dropdown

A labelled trigger that discloses a panel under it — the site header puts the language menu in one. It is a native details/summary pair, so the browser opens and closes it and announces the expanded state, with no script of the theme's own. theme.js adds only the dismissal: Escape, a click outside, and focus leaving the control.

It is a disclosure, not an ARIA menu: the panel holds ordinary links that Tab reaches. There is no aria-expanded — the details carries the state itself, and that is also what the stylesheet paints the open state from and what turns the chevron. The trigger's name is real text, visually hidden, so the header row keeps its width and the name is still translated with the page.

The panel is an ordinary absolutely positioned child of the component, not a popover in the top layer: a top layer box is positioned against the viewport, and pinning one under its trigger is what CSS anchor positioning is for, which is above the browser floor. So it opens under its trigger here, in the middle of this page. In the site header it is placed against the header instead and drops under it, because a panel under the trigger alone would cover the header's own navigation: the second row of a wrapped menu in the one row header, the navigation row in the other arrangements.

The trigger works on this page. In the screenshots of the visual suite it is shown closed, which is the state it renders in.

The panel keeps an id although nothing points at one any more - the "popovertarget" that used to is gone with the popover. It is part of the markup contract ("Partials/Page/Dropdown.html" takes "id" as a required argument), a specimen that dropped it would show a contract the theme does not render, and it is what an acceptance test or a site package addresses one particular panel by. "StyleguideRenderingTest::everyIdReferenceOnThePageResolves" checks references against ids and not the other way round, so nothing here fails either way; this note is why that is deliberate.

Content menu

The shared component behind every menu_* content element: a list of links, each optionally carrying a date (menu_recently_updated) and an abstract (menu_abstract), plus a nested --sub list for the one element that is a tree rather than a flat list (menu_sitemap). The first item below has both optional parts, the second has neither — they are omitted from the markup entirely rather than rendered empty, the same rule the navigation components follow for aria-current. The nested list uses --sub at every depth, not a name per level, because the recursion does not know in advance how deep a sitemap goes. Current is marked by weight rather than a fill: this list sits in the content column, where a solid bar the width of the text measure would read as a callout.

Social links

The row theme_sociallinks renders: one entry per platform, each a link with the platform's logo from the vendored brands set and the platform's name as text. Where a logo came out the name is hidden visually and goes on naming the link; where none did — no logo was picked, or the set no longer has the name — the name stays visible and the entry is an ordinary text link. The stylesheet decides that with :has(.theme-icon) rather than a class the template writes, because the logo is rendered optional and a class decided earlier would hide the name of an entry that has nothing else. The first two entries below have a logo, the last two have not.
