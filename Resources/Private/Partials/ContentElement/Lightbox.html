The enlarged images of one gallery, in a dialog - what the editor's "Enlarge on click" field ("image_zoom") produces once there is a script. Rendered once per element by "Partials/ContentElement/Gallery.html", after the gallery itself; the contract is "Resources/Private/Scss/components/_lightbox.scss". --- The link is still the fallback ------------------------------------- The zoom link in the gallery keeps its "href" to the file and is **not** a "data-theme-dialog-open" opener. That attribute is hidden while the root carries no "data-js" ("components/_dialog.scss"), which is right for a button that could do nothing - and wrong for this one: without a script the link still opens the image, exactly as it did before this dialog existed. It carries "data-theme-lightbox" instead, which nothing hides, and "theme.js" calls "preventDefault()" on it. A closed dialog renders nothing at all, so a page whose script never runs carries this markup and shows none of it. --- One item per image, addressed by its reference ---------------------- Each item carries the id of the file reference it shows, and the zoom link of that image names the same id. Nothing counts: a gallery of a "textmedia" element may hold a video between two images, and an index would have to agree with a list this template does not have. Only images are in here, by the same "file.type" the gallery partial branches on. A video or an audio file has no enlarged form - it is played where it stands - and gets no zoom link either. The two arrows are always rendered and the script hides them where there is only one item: how many of the files are images is known there, after the loop below, and counting them again in Fluid would be a second answer to the same question. --- The picture is the file, not the thumbnail -------------------------- "f:image" without a width hands out the original file, which is the point of enlarging it. The thumbnail in the gallery is the processed one, and the two are different files whenever the gallery scaled anything down. "alt" and "title" are not passed, for the reason the gallery partial gives: the ViewHelper takes them from the file reference itself.
No "value": the close button of the dialog contract carries "value=cancel" so that whatever reads "returnValue" cannot tell it from the cancel button beside it. Nothing reads it here, and there is no second way of closing to tell it from.
Both are "type=button": inside a "form method=dialog" a button without a type is a submit button, and the first arrow press would close the lightbox instead of moving it.
