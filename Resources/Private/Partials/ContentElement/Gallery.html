The gallery of a content element, as "GalleryProcessor" computed it: rows, columns, a position, and a width and a height for every media element. The processor has already decided the column count from "imagecols", so the stylesheet must not impose one of its own - the editor's "Number of columns" would stop meaning anything. The count is exposed as a data attribute for CSS that wants to react to it. The width and height are rendered as attributes rather than left to CSS. They are what lets the browser reserve the box before the image has loaded, which is the difference between a page that settles and a page that jumps. "intext" - the text flows around the gallery - is translated into a float: "--float-start" for "In text, left", "--float-end" for "In text, right", and "--nowrap" on top for the two "no wrap" variants. The processor's own two positions stay on the wrapper as they were. See "components/_gallery.scss" for why the modifiers are logical. Every item is a ".theme-figure" as well, and its caption a ".theme-figure__caption" - the figure component the gallery builds on. --- Not every file in a gallery is an image ---------------------------- "textmedia" reads "assets", which takes any media type, so a column may hold a video or an audio file. "file.type" says which - 2 an image, 3 audio, 4 video - and it is read through "getType()", which returns the same "int" on 12.4.45 and 13.4.35 (verified in "AbstractFile::getType()"). The integers are the "FILETYPE_*" constants of "AbstractFile" on v12.4, and the cases of the "FileType" enum that superseded them on v13.4 (Feature #102032, 13.0, which deprecated the constants and not the method); the values are the same on both. A video or an audio file is played where it stands, as ".theme-media" - see "components/_media.scss" for why the tag is written here rather than left to "f:media". The gallery item is the figure of that component as well as of the figure component, which is what lets the caption stay the gallery's. Anything else - a PDF that reached "assets" before an integrator narrowed the field - falls through to the image branch, where "f:image" is what the element has always done with it.
The dialog the zoom links open, once per element and after the gallery - a closed dialog renders nothing, so its place in the flow is free. Only the images of the gallery are in it; see the partial. One line on purpose: the output lands inside the "class" attribute, and a line break there would be part of the attribute value. theme-gallery--float-start theme-gallery--float-end theme-gallery--nowrap "alt" and "title" are not passed: the view helper takes them from the "alternative" and "title" properties of the file reference by itself, and passing an empty string would suppress that fallback rather than fill it in. The item is a ".theme-media" as well as a ".theme-figure", so the caption below is the one caption of the item rather than a second one inside a nested figure. No width or height attribute: "GalleryProcessor" computes both from the file's own dimensions, and a video or an audio file has none in FAL, so what it computes is a width of the column and a height of zero. The component sizes the player instead. "preload=metadata" rather than "auto": a gallery may hold several players, and none of them is what the reader came for. "playsinline" keeps a video in its box on iOS instead of taking over the screen the moment it starts. The caption track of a media file, from the "tx_theme_captions" field of the element - a field of this extension, because a file reference has none: "sys_file_reference" carries a title, a description, an alternative text, a link, a crop and "autoplay", and nothing that could hold a WebVTT file. A caption file belongs to the media file **of the same name**: "launch.vtt" captions "launch.mp4". Pairing by position in the two lists was the alternative and was rejected - an image added in the middle of "assets" would silently re-point every caption after it, and nothing about the page would look wrong. No "default" attribute. It would switch the captions on, which is the friendlier default, but it is valid on one track per kind only, and two files of the same name in different folders would put it on two. No "srclang" either: it is required for "kind=subtitles" - a translation, which has to say which language it is - and optional for "kind=captions", which is the transcript of what is spoken in the language that is spoken. The label names the track in the browser's menu, and falls back to a translated word rather than to nothing. {caption.title}
