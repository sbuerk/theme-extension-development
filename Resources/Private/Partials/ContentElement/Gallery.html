The gallery of a content element, as "GalleryProcessor" computed it: rows, columns, a position, and a width and a height for every media element. The processor has already decided the column count from "imagecols", so the stylesheet must not impose one of its own - the editor's "Number of columns" would stop meaning anything. The count is exposed as a data attribute for CSS that wants to react to it. The width and height are rendered as attributes rather than left to CSS. They are what lets the browser reserve the box before the image has loaded, which is the difference between a page that settles and a page that jumps. "intext" - the text flows around the gallery - is translated into a float: "--float-start" for "In text, left", "--float-end" for "In text, right", and "--nowrap" on top for the two "no wrap" variants. The processor's own two positions stay on the wrapper as they were. See "components/_gallery.scss" for why the modifiers are logical. Every item is a ".theme-figure" as well, and its caption a ".theme-figure__caption" - the figure component the gallery builds on.
One line on purpose: the output lands inside the "class" attribute, and a line break there would be part of the attribute value. theme-gallery--float-start theme-gallery--float-end theme-gallery--nowrap "alt" and "title" are not passed: the view helper takes them from the "alternative" and "title" properties of the file reference by itself, and passing an empty string would suppress that fallback rather than fill it in.
