Shared by theme_hero, theme_hero_small and theme_hero_text_only - the three variants of the step-5c contract differ only in the "compact" argument (theme_hero_small passes 1) and in whether "files" resolves to anything: theme_hero_text_only has no "image" field at all (see its TCA), so ContentElements.typoscript wires no FilesProcessor for it and "files" is simply never part of the arguments that CType's template passes down - "{files.0}" then resolves to null through Fluid's ordinary missing-variable handling, the same way "{data.tx_theme_link}" already does everywhere else in this extension for an unset field. Markup contract: Resources/Private/Scss/components/_hero.scss. "tx_theme_eyebrow" is the short label above the title, as ".theme-hero__eyebrow" - a paragraph before the heading, not part of it, so the heading stays the text of the outline. "tx_theme_hero_layout" picks a modifier: (empty) the image beside the text, at the start no modifier image-end the image beside the text, at the end "--image-end" centred centred, the image above the text "--centred" screenshot centred, the image below the text, "--screenshot" cut off at the bottom edge of the hero bordered the image at the end, cut off at the "--bordered" end and bottom edges of the hero The three that arrange an image need one. Without an image, "image-end" and "bordered" render the default - there is nothing to move - and "screenshot" renders "--centred", which is what it is without its image. Any other value renders no modifier, the rule of the frame modifiers in "Layouts/ContentElement.html"; "ContentElementContractTest" holds every modifier written here to a rule of the stylesheet. "screenshot" is the one layout that changes the order of the markup: the image follows the text, so the order a screen reader reads is the order on the screen - "mediaAfterText", set inline so that the component contract test, which reads every "f:variable" tag of this file as classes, does not take it for one. "image-end" and "bordered" keep the image first and move it with the stylesheet, like ".theme-teaser--reversed": an image beside a heading is not a sequence a reader depends on. The heading level follows "header_layout" the same way Partials/ContentElement/Header.html does for every other content element (case values "1".."5" map onto h1..h5, "header_layout == 100" hides the header entirely) - the only difference is the default (header_layout "0"), which falls back to h1 here rather than Header.html's h2: a hero is ordinarily a page's own top heading, which is also what "_hero.scss"'s own markup contract illustrates. The stylesheet only ever selects by class ("theme-hero__title"), never by tag, so this changes nothing about how the title looks, only what a screen reader or the outline algorithm sees - which is why Header.html itself is not reused here instead of switching independently: its own default is the wrong default for this component. {f:variable(name: 'mediaAfterText', value: 1)} theme-hero--media theme-hero--compact
