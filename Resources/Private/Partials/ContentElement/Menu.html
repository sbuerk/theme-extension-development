Shared list rendering for the nine "menu_*" content elements built on core "MenuProcessor" in "Configuration/TypoScript/ContentElements.typoscript" - all nine produce the same item shape ("title", "link", "current", "children", and "data", the full page row) regardless of which "special" produced it. Only the "
" itself and its translated "aria-label" are the calling template's own; everything inside it is this partial. Recursion follows "Partials/Navigation/Main.html": one "Item" section calling itself for "item.children" rather than the list markup written out once per level. "children" is only ever populated when the "levels" TypoScript option is more than 1 ("menu_section", "menu_section_pages", "menu_sitemap", "menu_sitemap_pages") - for a single-level menu the key is simply absent, "f:if" is false, and the recursive branch never fires. One section therefore serves both a flat menu and a whole sitemap tree with no level argument to gate it. "showAbstract" and "showDate" are the only two things that change what is rendered, not just what is listed - "menu_abstract" passes "showAbstract: 1" to read "item.data.abstract" and "menu_recently_updated" passes "showDate: 1" to read "item.data.SYS_LASTCHANGED", both already present on the page row "MenuProcessor" puts at "item.data" with nothing added by "dataProcessing" to reach them - see the header comments of "Templates/ContentElements/MenuAbstract.html" and "MenuRecentlyUpdated.html". Every other template renders this partial with neither argument, and both default to unset/false. The boolean conditions below write the double-ampersand operator raw, never HTML-entity-escaped: an escaped form is valid XML and silently evaluates true regardless of the operands, since "BooleanParser" matches the literal token and Fluid decodes no entities. TYPO3 core itself never escapes it in a Fluid condition. Empty guard: no items means no list at all, not an empty one - whether that also means no "
" is for the calling template to decide.
