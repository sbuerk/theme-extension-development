The "theme_link" palette (tx_theme_link + tx_theme_link_label + tx_theme_link_variant, Configuration/TCA/Overrides/tt_content.php), rendered as a ".theme-button" (Resources/Private/Scss/components/_button.scss). Shared by the three hero variants, theme_teaser and theme_media_teaser - theme_testimonial does not carry this palette at all, see its own template. "tx_theme_link" is a TCA type=link field. Its stored value is already a stdWrap.typolink parameter string (the page/file/url/email/record syntax TYPO3\CMS\Core\LinkHandling\LinkService writes), which is exactly what "f:link.typolink"'s "parameter" argument expects (.Build/vendor/typo3/cms-fluid/Classes/ViewHelpers/Link/TypolinkViewHelper.php, "$this->arguments['parameter']" fed straight into "TypoLinkCodecService"). That ViewHelper renders through "ContentObjectRenderer::typoLink()" rather than assembling a tag itself, so the whole stored parameter string is handed to TypoScript and nothing about the link syntax is re-implemented here. "tx_theme_link_variant" only ever holds '', 'secondary' or 'ghost' - read from the "items" of "tx_theme_link_variant" in Configuration/TCA/Overrides/tt_content.php, not assumed. The switch below covers exactly those values and no more, matching the two modifiers "_button.scss" actually ships ("--secondary", "--ghost"); the empty default case renders the plain ".theme-button". {data.tx_theme_link_label} {data.tx_theme_link}
