A link with its label, style and icon, rendered as a ".theme-button" (Resources/Private/Scss/components/_button.scss). Arguments: "link", "label", "variant" and "icon" - the "theme_link" palette of a content element (tx_theme_link, tx_theme_link_label, tx_theme_link_variant, tx_theme_link_icon, Configuration/TCA/Overrides/tt_content.php) for the three hero variants, theme_teaser, theme_media_teaser, theme_text_icon and both links of theme_cta, whose second link fills the same four arguments from its own columns, and the "theme_link_style" palette of an inline list item (link, link_label, link_variant, link_icon) for a card of theme_card_group. The fields are passed in rather than read off "data", so one partial and one set of cases serves both. theme_testimonial does not carry a link at all, see its own template. A link without a label renders with no content at all, and the core fills in its fallback text: the title of the page for a page link ("PageLinkBuilder::parseFallbackLinkTextIfLinkTextIsEmpty()", read on v12.4.45 and v13.4.35 - "f:link.typolink" hands its rendered children to "typoLink()", so an empty tag is an empty link text), the address for an email link, the URL otherwise. Never the stored link reference, which would put "t3://page?uid=…" on the button. The icon is left out then: it would make the content non-empty, and the core would keep a button with an icon and no name. "tx_theme_link" is a TCA type=link field. Its stored value is already a stdWrap.typolink parameter string (the page/file/url/email/record syntax TYPO3\CMS\Core\LinkHandling\LinkService writes), which is exactly what "f:link.typolink"'s "parameter" argument expects (.Build/vendor/typo3/cms-fluid/Classes/ViewHelpers/Link/TypolinkViewHelper.php, "$this->arguments['parameter']" fed straight into "TypoLinkCodecService"). That ViewHelper renders through "ContentObjectRenderer::typoLink()" rather than assembling a tag itself, so the whole stored parameter string is handed to TypoScript and nothing about the link syntax is re-implemented here. The style - "Link style" in the form, "tx_theme_link_variant" and the "link_variant" of the child, which carries the same configuration - only ever holds '', 'secondary', 'ghost' or 'link', read from the "items" of the column, not assumed. The switch covers exactly those values, one per modifier "_button.scss" ships; the empty default case renders the plain ".theme-button". "ThemeLinkRenderingTest" holds the items and the cases to each other. The icon is an icon of the shipped set an editor picked, and goes before the label: it says what the link leads to, and leaves the end of the link to what says how it opens. It is decoration, hidden from assistive technology; the label names the link. The button's "gap" spaces it, in reading order, so it also comes first in a right-to-left page. "optional": a name a later Font Awesome version dropped loses the icon, not the page. {label}
